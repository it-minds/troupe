### D130 - Extends, the push policy, rules on profiles and the test guards after chunk 37 (low)

- **Profiles that extend another** (Decisions 908, 910 and 913).
  - Sessions pin a bundle version number, not its channel, and composition makes channel moves more common.
  - A profile that stops extending loads its channel's plain bundle until the next recompose.
  - In GitOps, a child's own manifest change runs its last profile in effect until the plane's next pass. Admission judges a child's spec write against its previous effective profile. A parent deleted in Git leaves the child refused but running its last profile in effect.
- **The fix loop's push policy** (Decision 911).
  - There's no content scan: a secret pasted into an ordinary file isn't caught by the path denylist. GitHub's push protection on the App's repositories covers it.
  - A clone-only profile that doesn't declare the API host can't revoke its clone token from the pod.
- **Triggers and identity** (Decisions 912 and 914).
  - Folding a refused adoption pair keeps one key-manager name, so a private session the folded row made won't open.
  - There's no editor for rules under the organisation's `defaults:`, which the plane doesn't store.
- **Tests** (Decision 915).
  - A first turn takes about 3 s unloaded on a Windows checkout over WSL, 1.3 s of it in `Troupe.Tools.available/2`. Under load that fails gateway `WaitingSessionsTest` and core `RememberTest`, and is probably D8's slow first turns.
  - CrashLoop restart intensity is counted in time, so restarts slower than about 1.7 s may never trip it. Unconfirmed.

### D131 - First run, GitHub sweeps, the signed plane and the agent picker after chunk 38 (low)

- **The desktop's first run and sign-in** (Decision 916).
  - The cause of a lost `setup.answer` reply on a real daemon wasn't found; both clients now recover from one, but the daemon side was only reproduced with the fake.
  - The desktop asks its updater about a recommended version older than itself; harmless, but it shows a fetch error when the release URL is unreachable.
- **GitHub sweeps and the App from GitOps** (Decision 917).
  - A sweep reads at most 50 issues and the first 100 open pull requests per run, and reuses the trigger's `last_fired_at`.
  - In GitOps mode, the App's settings and the teams' GitHub lists lock after the upgrade until `github/github.yaml` is committed; a team the manifest doesn't name lists no repositories.
  - The GUI's fake admin refuses `admin.github.delete` in every GitOps case, including `missing`, which the plane allows.
  - #653 still owes naming the person in each commit (`Requested-By:`) and the console's test token for a chosen repository.
- **A pod session's config** (Decision 918).
  - A session reports what it resolved when it started; a laptop's plain `/settings` reads the files as they are now.
  - About 65 `expect(button(…)).toBeNull()` checks after async steps stay unchecked; they can't flake, but some may pass before the thing could have been drawn.
- **The signed plane** (Decision 919).
  - The key is trusted on first use: whoever answers for the plane at a machine's first sign-in can get their key pinned.
  - The pin file lives in the person's own state directory, beside the cached document it protects.
  - `/downloads` is anonymous, so a 404 there tells anyone which versions are refused.
  - `initialize`'s `update_required` is unsigned.
  - The desktop's own updater doesn't yet verify the plane's signature against the daemon's pin; a policy change doesn't reach connected clients until they ask again; mirroring a release into the object store is by hand.
- **The agent picker** (Decision 920, tui/0164).
  - A bundle draft is refused if an agent has no `mode` or has a key no agent has, which also blocks publishing an older version that carries one again.
  - The console's `recordCalls()` swaps `fetch` after the admin client is built, so `bundles.test`'s "publishes nothing" passes without checking.
  - The GUI's fake `checkAgent` lacks `delegation` and has a shorter tool list than the harness.
  - #594 still owes `/agents` and `/new` onto the TUI picker, new-from-template, the desktop's agent manager on the picker, and the builder's profile-first view.

### D132 - Steering, company memory, MCP sign-in and the docs after chunk 39 (low)

- **Steering a laptop's session** (Decisions 921 and 928).
  - The console signs in admins only, so a person who isn't one steers only from the desktop app or the TUI.
  - Who is steering is polled in the desktop app.
- **The criticals sweep** (Decision 923).
  - A viewer still sees a pod session's models and prices.
  - Left with reasons: D5, D40's annotation latency, D48, D54 (needs a decision on `host:port`), D65's subagent spend, D71 and D92.
- **Offered tools and MCP sign-in** (Decision 924).
  - A URL-only server entry that answers 401 still needs `"oauth": {}`; signing in to a server that publishes RFC 9728 metadata by default would follow.
  - Troupe's client ID metadata document is at `https://it-minds.github.io/troupe/oauth/client.json`: moving the docs site breaks every provider that knows Troupe by that id.
  - A provider that registers Troupe only as a confidential client is refused.
  - Neither client's MCP view says which client a sign-in used, and the desktop app still draws nothing for `tools_registered`.
- **The docs** (#76, #189, #422).
  - Eight pages are over 400 lines: `ARCHITECTURE.md`, the prompt-prefix page, `admin/github.md`, `profiles-and-policy.md`, `user/configuration.md`, the TUI README, `admin/configuration.md` and `admin/installing.md`.
  - The repository's homepage link isn't set, and the docs site has no domain of its own.
  - D75: a decision's `symbols:` is still not checked against the code.

### D133 - Offers, memory refresh, the signed policy and the picker after chunk 40 (low)

- **Offered sessions** (Decision 928).
  - A grant whose release never reached the plane stays in `remote_grants` until the 30-day idle limit refuses it; nothing deletes it, and the console doesn't list a person's laptop grants.
  - The TUI still offers "allow for the session" on a relayed approval; the laptop refuses it with a sentence.
  - An offer doesn't come back after a reboot unless the person has `troupe-daemon login on`.
  - The gateway's `OrganisationTest` sees a late `config.changed` inside a 300 ms refute, under load.
- **Company memory** (Decision 929).
  - A change to a profile's `extends` reaches its running sessions only at their next activation.
  - A laptop session resumed after going dormant reads the current copy with no `memory_changed` line.
  - `organisation.json` stays after sign-out, where `memory.json` is dropped.
  - `PROTOCOL.md` has no section for the plane-to-pod pushes (`session.activate`, `session.memory`).
- **The signed policy and releases** (Decision 931).
  - There's no `admin.releases.remove`, and a failed mirror shows only in the audit and the log.
  - A mirror holds one file in memory at a time, up to about 100 MB.
  - The TUI's own HQ connection doesn't act on a `versions` change.
  - Re-resolving a running session for an organisation change also picks up the person's own config edits since it started.
  - `policy.revision` is unsigned; a forged one can only cause or suppress a fetch.
  - Gateway tests that wait 5 s on a link's background task fail under load.
- **The picker and the App** (Decision 932, tui/0166).
  - The admin API's flat `profile` argument receives the params map when absent; `profile_choices` guards for it.
  - The desktop's `AgentEditor` doesn't show `delegation`.
  - `Ledger.models_run` has no time bound.
  - The model picker offers only the models the plane knows; the plane never asks a provider for its list.

Found by the chunk 40 fixers, 2026-10-24.

### D134 - The gate's desk walk, the chart's hand steps, the upgrade test and the seam after chunk 41 (low)

- **The gate** (Decision 933). Walked at a desk on the installed 0.24.0-beta; the live rows are
  walked on 0.25.0-beta (`Stage 1 gate: v0.25.0-beta`).
  - Not walked at the desk: the desktop app on the trap repository (row 1 step 4) and on a real
    repository (row 3 step 5), the installer's own questions and its PATH change, and `cost_usd`
    against a provider that reports no price.
  - On Linux with `TROUPE_INSTALL_DIR` set, output redirected with a plain `>` is overwritten by
    Burrito's `[i]` lines, which reach the file through a description of their own.
- **The chart and the operator** (Decision 934).
  - Still by hand on a cluster: copying the worker Secrets into each new worker namespace, and
    the `troupe.dev/ingress=true` label.
  - `SecretMissing=True` shows on a freshly installed profile right after the install although
    the Secrets exist.
  - The kind plane holds OpenBao's root token, so the cluster suite never exercises the grant
    check with a narrow role; the GitHub grant is always reported optional, an App configured or not.
  - `scripts/kind-up` under Git Bash needs `MSYS_NO_PATHCONV=1` (`chmod /kind` is
    path-converted); `kind-upgrade-check` sets it, `kind-up` does not.
  - The e2e `enrolment_test` depends on an earlier test writing the profile row;
    `Troupe.Plane.ClusterTest` times out starting its replica on a loaded machine.
- **The mediums** (Decision 935).
  - `pnpm audit` in `clients/gui` reports `undici` below 8.12.2 through `jsdom` (test-only).
  - No CI job runs the desktop crate's `cargo test` or the protocol keyring test on Windows, so
    the Windows half of the parts layout is checked on a developer's machine only.
  - After a renewal whose store write failed, the rotated-away token stays stored; the next
    launch's refresh is refused once and clears it.
  - Windows PowerShell 5.1 caps an environment value near 32 KB, so a keyring value of that
    size fails at the helper's hand-off, not at Credential Manager.
- **The upgrade** (Decision 936).
  - `helm rollback` is tested nowhere; `upgrading.md` says so.
  - `scripts/e2e` never runs `deps.get` in the toolbox; a stale shared deps volume fails the
    first seed.
  - The kind scripts need bash (arrays); `sh -n` under dash refuses them, as `remote-up`
    already did.
- **The seam** (Decision 937).
  - The 4096-byte line `security -i` takes is Apple's documented limit, not measured here; the
    daemon uses the parts layout past it on macOS.
  - The umbrella `.formatter.exs` covers the root's `config`, `lib` and `test` only, so the
    format check does not cover `apps/`.
